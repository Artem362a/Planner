# Экспериментальный MCP-доступ

Day Plan публикует удалённый MCP-сервер по каноническому адресу
`https://<домен>/mcp/`. Адрес без завершающего слэша отвечает `308` с сохранением HTTPS и
метода запроса.
Он предназначен для AI-клиентов с поддержкой Streamable HTTP и OAuth. Клиент
не получает пароль пользователя и не обращается к PostgreSQL напрямую: каждый
вызов проходит через серверные инструменты Day Plan, проверку scope и фильтр
`user_id`.

## Как включить

1. Пользователь с ролью `developer` открывает в левом меню
   «Экспериментальные функции» и добавляет нужный аккаунт в allowlist.
2. Пользователь добавляет показанный на странице MCP URL в совместимый AI-клиент.
3. Клиент регистрируется как публичный OAuth-клиент и открывает страницу входа
   Day Plan. После входа пользователь отдельно выбирает разрешения.
4. Разрешения на удаление по умолчанию выключены на экране согласия и требуют
   ручного включения.
5. Подключение и последние вызовы видны на той же странице; подключение можно
   отозвать в любой момент. Удаление из allowlist отзывает все подключения
   аккаунта немедленно.

## OAuth

- Authorization Code Flow с обязательным PKCE `S256`.
- Публичные клиенты регистрируются через Dynamic Client Registration;
  `token_endpoint_auth_method=none`.
- Текущий rollout не объявляет Client ID Metadata Documents: их поддержка
  потребовала бы безопасно загружать произвольные HTTPS-документы на сервере и
  заметно расширила бы SSRF-поверхность. DCR оставлен как совместимый fallback
  для новых клиентов и основной механизм для клиентов прежних версий MCP.
- Redirect URI должен в точности совпадать с зарегистрированным. Разрешён HTTPS;
  HTTP разрешён только для loopback-адресов `localhost`, `127.0.0.1` и `::1`.
- Access token непрозрачный, действует 30 минут. Refresh token действует 30 дней,
  ротируется при каждом использовании; повторное предъявление старого refresh
  token отзывает всё подключение.
- В БД хранятся только HMAC-SHA256-хэши токенов и кодов. Токен привязан к одному
  MCP resource через OAuth Resource Indicators.
- Authorization request живёт 10 минут, одноразовый authorization code — 5 минут.

Discovery:

- `/.well-known/oauth-protected-resource/mcp/` (вариант без завершающего слэша сохранён как
  совместимый alias)
- `/.well-known/oauth-authorization-server`
- `/api/oauth/register`, `/api/oauth/authorize`, `/api/oauth/token`,
  `/api/oauth/revoke` в production-конфигурации nginx.

## Разрешения

| Scope | Возможности |
|---|---|
| `planner:read` | планы дня/недели, входящие, цели, статистика, заметки, категории, напоминания, шаблоны |
| `tasks:create` | создание задач дня, недели и входящих |
| `tasks:edit` | редактирование, завершение, перенос и назначение задач |
| `tasks:delete` | удаление задач дня, недели и входящих |
| `goals:create` | создание целей и этапов |
| `goals:edit` | редактирование целей и этапов |
| `goals:delete` | удаление целей и этапов |
| `organizer:edit` | запись заметок, настройка начала дня, создание/изменение категорий и напоминаний, применение шаблона дня |
| `organizer:delete` | удаление категорий и напоминаний |
| `schedule:read` | только чтение университетского расписания |
| `feedback:read_all` | только чтение отзывов всех пользователей; scope работает только при актуальной роли `developer` |

`planner:read` обязателен. Обычному пользователю нельзя выдать
`feedback:read_all`, даже если клиент его запросил.

## Что MCP принципиально не умеет

- удалять аккаунт;
- менять имя, аватар, тему или пароль;
- читать, создавать и отзывать web-сессии;
- привязывать или отвязывать Telegram;
- изменять или синхронизировать университетское расписание;
- отвечать на отзывы, менять их статус или выполнять другие developer/admin
  операции.

Наличие роли `developer` управляет allowlist, но не отключает ownership-проверки:
обычные инструменты разработчика всё равно работают только с его собственными
задачами и целями. Единственное межпользовательское исключение — отдельный
read-only инструмент отзывов с двойной проверкой роли и scope.

## Реализация и аудит

MCP-инструменты находятся в `backend/mcp_server.py`, OAuth — в
`backend/routers/mcp_oauth.py`, управление из интерфейса — в
`backend/routers/experimental.py`. Все успешные и ошибочные вызовы инструментов
записываются в `auth.mcp_audit_log`; содержимое заметок, описаний, сообщений и
подзадач в аргументах маскируется.

Для production задать отдельный случайный `MCP_TOKEN_PEPPER` и публичные URL:

```env
PUBLIC_APP_URL=https://dailyplannerapp.ru
PUBLIC_API_URL=https://dailyplannerapp.ru/api
MCP_RESOURCE_URL=https://dailyplannerapp.ru/mcp/
OAUTH_ISSUER_URL=https://dailyplannerapp.ru
MCP_TOKEN_PEPPER=<отдельный длинный случайный секрет>
```

Перед запуском новой версии применить миграцию `alembic upgrade head`, затем
обновить nginx из `deploy/nginx.conf`. Production-развёртывание выполняется
только отдельно и после резервной копии БД.
